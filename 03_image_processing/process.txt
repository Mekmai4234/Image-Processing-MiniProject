PROCESS — หลักการ Input/Output และเกณฑ์รับงาน

อัปเดต 21 ตุลาคม 2026
- build_detector_config รับ dict/catalog/manifest/source RGB และ file hashes จาก loader ของ 04
  ตรวจ development references, crop hash และ report ที่ตรง config/dataset version ก่อนเปิด validated
- annotate_fields/annotate_image แสดง result/MATCH จาก similarity จริง, reason และ expected ROI เส้นประ
- analyze_shape คืน bottle-silhouette-v1/mask/contour/radial profile แยกจาก InspectionResult
  segmentation ใช้ implementation ร่วมกับ locator 03; failure คืน fallback ไม่เปลี่ยนผลฉลาก
- HTTP inspection tests เรียก detector จริงแล้ว แต่ HTTP locator/stored annotation ของ 04
  ยังต้องนำจุดเชื่อมไปใช้ ไม่แก้ไฟล์ของ 04 ในรอบนี้
- หลักฐานทั้งหมดของ 03 ยังเป็น synthetic tests ไม่มี real-data accuracy/shape validation

Input
image, supporting images, expected_product, source_mode, evidence และ config_version
ใช้ evidence.kind/search_status/มุมตาม API contract v0.2; งาน 04 แปลง multipart ให้ pure functions
ผลประมวลผลภาพเป็นความจริงจาก pixels ไม่ใช้ filename/โฟลเดอร์คำตอบเป็น feature

Pipeline
Decode → Quality gate → Bottle ROI → Label candidates → Normalize
→ Compare templates → Check product/position → Decision → Annotate
median/average ใช้ลด noise เมื่อจำเป็น, HSV ใช้แยกสี, morphology เชื่อม/ลบจุด,
edge/contour ช่วยหาฉลาก; เลือกจากปัญหา ไม่บังคับใส่ทุกเทคนิคในทุกภาพ

Output
InspectionResult ตาม docs/api-contract.md: result, reason, detected_product,
match_score, score_method, bbox/expected_bbox, image size, timing และ config_version
หากไม่พบ candidate ให้ bbox=null; ไม่สร้างกรอบวัตถุสมมุติ

Score
match_score = คะแนนความคล้าย (0..1), ไม่ใช่ probability
score_method=template_ccoeff_normed_clamped_v1: รับ raw finite [-1,1] แล้ว max(0,raw)
input/template ไม่มี variance หรือ raw ไม่ finite → score=null, REVIEW ambiguous_match
wrong_label อาจมี match_score สูงต่อสินค้าที่ตรวจพบได้ แต่ยังเป็น FAIL
ไม่พบฉลาก / ภาพเบลอ / ไม่สามารถจับคู่ ให้ score=null แทนตัวเลขสุ่ม
ตรวจ tolerance และกฎ product แยกจาก score; คะแนนสูงไม่ได้ข้ามกฎตำแหน่ง

Orientation
locator คืน usable_view, bbox, image_width/image_height, quality และ reason ตาม contract
quality มี sharp_enough/label_visible/bottle_visible; งาน 02/04 ควบคุมการวนภาพ/การจับภาพ
ฉลากคนละชนิดแต่เห็นชัดยัง usable_view=true; อย่าใช้ expected_product กรองจนมองข้ามฉลากผิด
เห็นเฉพาะ label crop แต่ประเมินตำแหน่งบนขวดไม่ได้ยังไม่ usable
เมื่อค้นหา exhausted/timed_out ให้ส่งภาพหลักที่ดีที่สุดและ supporting images ไปตัวตรวจเสมอ
ถ้าไม่มีหลักฐานพอ → REVIEW orientation_failed แล้วบันทึก History ผ่านคนที่ 4
ภาพเดียวเบลอ/ฉลากหันหนีใช้ blurred_image/label_not_visible ตามสภาพจริง
FAIL missing_label ได้เมื่อ Backend ตรวจหลักฐานผ่าน required-view profile ที่ validate แล้ว
reported_coverage_deg และมุมจาก client เป็นข้อมูลประกอบ ไม่ใช่คำยืนยันว่าตรวจครบ
ส่ง verified_coverage/required_view_profile และรายชื่อภาพหลักฐานให้คนที่ 4 เก็บย้อนหลัง
Webcam ให้ผู้ใช้หมุนเองจนภาพ usable; กล้องหน้าเดียวไม่สามารถยืนยันมุมที่ไม่เห็น

Error handling
ไฟล์เปิดไม่ได้/API error เป็น operational error ไม่ใช่ผลผิดปกติของขวด
ภาพเบลอ, แสงสะท้อนบัง, ฉลากหันหนี อาจเป็น REVIEW ตาม evidence
ยี่ห้อที่อยู่นอก catalog ให้ REVIEW unknown_product ไม่เดาเป็นชนิดที่รู้จัก

เกณฑ์ส่งมอบ
pure functions ทดสอบได้, deterministic สำหรับ config เดียวกัน,
มีผลเทียบ ground truth หลายขวด/หลาย session, ไม่ฝึก/ปรับเกณฑ์จาก test set,
กรอบกับ annotation ตรงภาพ และเปิดเผยข้อจำกัดกับสภาพแสงจริง
