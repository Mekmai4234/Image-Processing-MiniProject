PROCESS — หลักการ Input/Output และเกณฑ์รับงาน

Input
Job = {job_id, expected_product, views:[{angle_deg,image}], speed}
ผล locate/orientation และ InspectionResult รับจากคนที่ 4 โดยอัลกอริทึมคนที่ 3

Output
Scene state, current_angle, current_station, progress และ event ของ job เดียว
ส่วน UI แสดง inspection result จาก Backend โดยไม่คำนวณ score ซ้ำในฉาก

การหมุน
การแสดง model หมุนกับการเลือกภาพที่ใช้ตรวจต้องสัมพันธ์ angle_deg
ตรวจทีละภาพ รอ response แล้วค่อยเลือกมุมต่อไป จำกัดจำนวนและเวลารวม
found = มองเห็นฉลากและมีคุณภาพพอ ไม่ใช้การนับวินาทีสมมุติแทนการค้นหา
single-view mode ตรวจภาพนั้นโดยตรงและแสดงข้อจำกัด ไม่รายงานว่าเห็นครบ 360 องศา

State และเวลา
ใช้ elapsed time จาก animation clock; pause ไม่เพิ่มเวลาจำลอง
Network timeout ใช้เวลาจริงแยกจาก animation speed
ถ้า reset/ออกหน้า ใช้ job token หรือ abort signal ละทิ้งผลเก่า
ห้าม transition WAIT_RESULT → PASS โดยอัตโนมัติเมื่อ API ช้า

Reject
คำว่า FAIL เป็นผลตรวจสินค้า ส่วน REJECT เป็นทางคัดออก
FAIL และ REVIEW อาจไปถาดเดียวกันได้ แต่ต้องมี reason ต่างกัน
sensor/กลไกเป็น simulation; webcam mode ไม่อ้างว่าหมุนขวดจริงด้วย browser ได้

ความเป็น 3D
เป้าหมายมี geometry, perspective, lighting และกล้องปรับมุมได้
prototype SVG เดิมไม่ใช่ completion ของงานนี้
ขวด texture จากรูปเป็น 2D representation เว้นแต่มีโมเดลหลายด้านที่ทีมจัดเตรียม

เกณฑ์รับงาน
ขวดไม่ข้ามสถานี, ไม่ชน/ลอย, ทาง pass/reject อ่านออก,
pause/reset ไม่เกิดผลซ้ำ, delayed response ไม่เปลี่ยนขวดผิดใบ,
การ replay ไม่เขียนฐานข้อมูลซ้ำ และมี fallback ถ้า WebGL ใช้ไม่ได้

ข้อตกลงที่เพิ่มใน M1 (19 ต.ค. 2026)
พบ usable view → ส่งภาพหลักภาพเดียว evidence single_view/usable_view_found ไม่ส่ง supporting_images
ค้นครบหรือหมดเวลา → ภาพตัวแทน + มุมที่ค้นแล้วเป็น supporting_images แล้วรอ Backend ตัดสิน
ภาพตัวแทนเลือกจาก quality ของ locator (bottle_visible > sharp/label) เสมอกันใช้มุมน้อยสุด
REVIEW มีช่อง "รอถ่ายใหม่" สีเหลืองแยกจากถาด REJECT ของ FAIL ฉากจึงมี 3 ปลายทาง
การเคลื่อนที่ทุกช่วงเป็น segment เวลาจำลองใน state machine; scene วาดตาม state อย่างเดียว

ข้อตกลงที่เพิ่มใน M3 (21–22 ต.ค. 2026)
